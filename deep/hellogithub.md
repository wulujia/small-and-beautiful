# HelloGitHub（削微寒）

> 给"不知道开源能干嘛"的普通程序员，每月挑一筐有趣、能跑起来的入门级开源项目 ｜ hellogithub.com ｜ 创始人：削微寒（网名，坐标北京）[9] ｜ 创刊 2016-05 [1] ｜ 1 人主理 + 志愿者团队（HelloGitHub-Team）[1][4] ｜ 类型：内容月刊 + 开源社区 ｜ 营收：未公开（已知 5 个常驻赞助位 + 捐赠）[8][10]

## 缝隙切入点

2016 年 5 月，削微寒——自述"普通本科、没大厂经历、大学打了四年游戏后自学 Python"的程序员——在 GitHub 闲逛时收集了 10 多个有趣项目，一是怕自己记性不好丢了，二是想帮和他一样摸不着门道的小白入门开源，于是整理成 markdown 发在 GitHub 上，这就是第一期 [1]。缝隙的本质：GitHub 上项目浩如烟海，但对中文新手没有一份"有趣、入门级、跑得起来、有中文说明"的导航。口号后来固定为"兴趣是最好的老师，HelloGitHub 让你对开源感兴趣"[10]。

## 差异化

- 只选"有趣、入门级"的项目，配中文说明，按语言分栏（C/C#/C++/Go/JS/Kotlin/Python/Rust/Swift + AI + 其它），第 123 期共 37 个项目 [10]。
- 选品标准明确反对唯流量："入选并不是按照 Star 增长或'出圈'程度作为唯一标准，而是更看重来自 HelloGitHub 社区用户的真实反馈"[7]。
- 最硬的差异化是更新纪律：固定每月 28 号发刊，原因是"不管是平年还是闰年，每个月都有 28 号，不给自己不发月刊找借口"[1]。从 2016 年 5 月到 2026 年 6 月连发 123 期，十年没断 [1][10]。2026-05-28 第 122 期恰好是创刊十周年整，正文一句纪念都没提，照常发刊 [12]。

## 第一批用户/冷启动

- 第一期发出后一个月，"意外收获约 20 个 star"，一度访问量寥寥、想过放弃 [1]。
- 是第一期下面的评论者留住了他："他们对新手真的十分友好，都是鼓励和点赞的"；读者"马三小伙儿"从第一期起几乎每期评论支持，"zhbzz2007"是第一位通过 issue 推荐项目的人 [1]。
- 早期靠博客园、掘金、V2EX 等平台转发扩散 [1]。第 1 年做到 12 期、star 破千 [1]。他的总结："使用者、关注的反馈真的是特别重要的，这些反馈能证明他的努力没有白费。"[1]

## 收入与定价

- 具体金额从未公开。月刊和 README 常驻 5 个赞助位（2026-06 第 123 期）：UCloud（GPU 云）、又拍云（CDN）、OpenIM（开源 IM）、七牛云、OfoxAI [8][10]；官网服务器由 UCloud、又拍云赞助提供 [11]。另有官网捐赠和 Buy Me A Coffee 入口 [8]。
- 赚钱状态他自己说得很直白：2021 年五周年反思"热爱 + 收入 = 活下去"[2]；2023 年 11 月自嘲"钱没赚到人还瘦了两圈"[5]；2025 年初的年度目标只有一句："让 HelloGitHub 保持初心地活下去！"[6]
- 仓库许可证是 CC BY-NC-ND 4.0（禁止商用、禁止演绎），把内容资产攥在自己手里 [8]。

## 内容与增长

增长时间线（star 为主仓库 521xueweihan/HelloGitHub）：
- 2016-05 创刊，首月约 20 star [1]
- 2017-06 一周年：12 期，star 破千 [1]
- 2021-03 五周年：3.9 万 star，累计推荐 1,574 个项目 [2]
- 2023-11：7 万+ star，社区 1 万+ 用户，全网自媒体 50 万+ 粉丝 [5]
- 2026-07：16.5 万 star、1.23 万 fork，为 GitHub 上最大的中文开源内容仓库之一；本人 GitHub 粉丝 1.31 万 [8][9]
- 2025 全年：发布 588 个项目，官网总 UV 1,253,290 [7]

内容矩阵围绕同一件事延伸：讲解开源项目系列、HelloDjango / HelloZooKeeper 教程 [2]；另一个项目 GitHub520（解决国内访问 GitHub 慢）2.91 万 star，反哺主品牌 [9]。2021 年 6 月他成为 GitHub 官方 Star（全球仅 300 席，当时中国仅 2 人：ECharts 的 Ovilia 和他），奠定其在中文开源圈的枢纽位置 [3]。他的座右铭写在 GitHub 签名上："时间会让平凡的事变得与众不同"[9]。

## 社区

- 2017 年第一版网站用 Flask + jQuery 上线；2023 年 1 月彻底重构，定位"开源项目的豆瓣"——用户可分享、评论、评分开源项目 [4]。
- 重构的分工方式很典型：他一个人写后端（FastAPI）和爬虫，前端公开招募，6 个月内 7 位志愿者贡献 400+ 次提交 [4]。
- 2024 年社区新增 1.5 万用户 [6]；2025 年月刊项目中 160 个来自用户投稿，占 27.2%——读者变成了共创者 [7]。
- 志愿者体系从早期就有：JS 专栏负责人小猴、Go 专栏雷神、设计 logo 的远哥，后来的喜斌、小飞、小季等按专栏分工 [1]。他的话："人一生都在路上，有的人走着走着就走散了。有的人走着走着就并肩作战了。"[1]
- 2023 年起计划采访民间开源作者、做视频、办线下"开源人火锅局"[5]。

## 留存

- 月刊本身就是留存机制：十年固定 28 号发刊，公众号、微博、RSS、博客园、掘金、知乎专栏多渠道同步分发 [8][11]。
- 但社区互动数据很轻：2025 年官网 125 万 UV，只换来 4,462 次收藏、650 条评论、5,936 次投票 [7]——典型的"高流量、轻互动"内容站，读者习惯是"每月来领一次清单"而非驻留。

## 转型

三次形态跃迁，方向始终没变：2016 年 GitHub 上的 markdown 月刊 [1] → 2017 年 Flask 个人网站 [4] → 2023 年社区化重构（"开源项目的豆瓣"，标签体系、用户投稿、计划中的 AIGC 推荐）[4][5]。每次转型都是"同一份月刊换更好的容器"，而不是换赛道。

## 如何保持小

- 核心动作十年不变：每月一期。所有新尝试（教程、讲解、访谈、视频、火锅局）都围绕"让人对开源感兴趣"这一件事 [2][5]。
- 组织上不雇人：后端一人，前端和专栏靠志愿者认领 [1][4]。名利态度见于 GitHub Star 获奖感言："这个荣誉不只属于我一个人……我做的事情，每个人都可以做而且能够做的比我还好。只要做个有心人！"[3]
- 十周年整（第 122 期）不办庆典、不发长文，照常发刊 [12]——纪律大于仪式。

## 开放问题（值得当面问本人的）

1. 现在是全职做 HelloGitHub 还是有主业？收入结构里赞助位、公众号推广、捐赠各占多少，能覆盖生活 + 服务器吗？
2. 5 个常驻赞助位怎么定价、怎么筛选？拒绝过什么样的钱（比如与"入门级、有趣"调性冲突的广告）？
3. 123 期里最接近断更的是哪一期？那个月发生了什么，怎么扛过去的？
4. 125 万 UV 对 650 条评论——你怎么看"高流量低互动"？2023 年花半年做社区化重构，现在回头看值吗？
5. 无薪酬的志愿者团队怎么维系十年？流失最痛的一次是什么时候？
